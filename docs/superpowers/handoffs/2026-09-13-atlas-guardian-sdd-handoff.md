## Architectural invariants

Do not create a second:

- workflow engine;
- state machine;
- tenant/org identity model;
- Approval Center;
- audit store;
- evidence store;
- Assistant truth store;
- Work-specific authorization authority.

Reuse the existing `packages/execution`, Guided Execution, `atlas-execution`, approval digest, evidence, RBAC, tenant scope, and audit contracts.

The canonical chain is:

`INTELLIGENCE -> DISCERNMENT -> AUTHORIZATION -> EXECUTION -> VERIFICATION -> EVIDENCE -> AUDIT`

## Non-negotiable Guardian behavior

- Cross-tenant and cross-organization execution fails closed.
- `execution.approve` in a step means approval is required; it does not require the executor to also be the approver.
- All other required task/step permissions must be satisfied before adapter/provider execution.
- Approval binds to the exact current task version and reviewed action payload.
- A materially changed payload invalidates stale approval.
- Required evidence must be present and verified before completion can be asserted.
- Adapter/provider success without verification is not completion.
- Assistant remains explanatory/navigation-only and cannot self-authorize.
- Unknown/disconnected/unverified provider state must never render as connected/healthy/completed.
- Guardian UI is enterprise-neutral; do not add religious imagery or impose a faith statement on customers.
- Accessibility-critical Guardian states must have textual semantics, keyboard support, screen-reader output, and non-color-only status.

## Cost and provider constraints

- No external paid-provider spend.
- No AWS EC2 provisioning.
- Do not create paid VPS/cloud runtimes.
- Do not mutate unrelated Cloudflare, Vercel, Supabase, DNS, billing, or provider configuration.
- The existing Work Soberano router-policy plan owns budget, autonomy, provider capability, and browser execution-envelope enforcement; do not duplicate it.

## Verification before completion

At the end of both phases, run at minimum:

```bash
npm ci
npm run typecheck
npm run test:unit
npm run test:integration
npm run build
npm audit --audit-level=high
```

Also run every focused test command required by both implementation plans.

Do not claim completion if any required verification did not run or failed.

## Final review

After every task is reviewed, dispatch the whole-branch final reviewer using `superpowers:requesting-code-review` on the full branch diff from merge-base to HEAD, including all deferred minors and ledger rulings.

If final review finds issues, perform exactly one final fix wave and one scoped re-review, then adjudicate any residuals according to SDD rules.

## Stop before merge/deploy

Do **not** merge to `main` and do **not** deploy production as part of this handoff.

Finish with `superpowers:finishing-a-development-branch` and present the verified branch/PR options to the user.
