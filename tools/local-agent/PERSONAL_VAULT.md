# Personal Vault — local development core

Status: predeploy, not a certified password manager. No real credentials imported.

## Implementation

`lib/personal-vault.mjs` reuses Local Core AES-256-GCM/scrypt persistence,
secure POSIX file modes, atomic replacement and exclusive writer locks.
The existing primitive and its tests are present in the available
`origin/main` snapshot `6f7bc8bf7ccb4c50afb347281c934b4cf1925786`.
`memoryUpdate` adds locked read/modify/write so concurrent imports cannot
silently overwrite one another. A busy writer rejects with `vault_locked`.

The factory requires an absolute path to a dedicated private directory.
Do not use the AI memory directory: its generic readers must not access
personal credentials. Every operation requires the passphrase; there is no
cached unlock, network request, logging, MCP registration or HTTP endpoint.
The owning OS account remains the local trust boundary. This does not
implement server RBAC, tenant isolation, biometric unlock or remote sync.
JavaScript strings cannot be reliably erased from process memory.

CSV column adapters accept Google `name,url,username,password,note` and
Apple `Title,URL,Username,Password,Notes`. Extra columns are ignored;
passkeys, TOTP seeds, attachments and arbitrary export versions are not
supported. Headers/CSV shape are checked, and malformed input fails the
whole import. Only HTTP(S) URLs without embedded credentials are accepted;
URLs are never fetched. Duplicate URL/username pairs skip identical
password/notes and reject conflicts without committing any row. No automatic
replacement is performed. Sources are preserved on imported records.

Search returns identifiers and account metadata only. Passwords, notes and
recovery codes cannot match search queries. `reveal` is for an explicit
trusted local user interface only; never expose it to a model or ChatGPT
tool. Recovery codes remain a separate per-account field and are never
generated by this module. Import accepts at most 1 MiB and 500 accounts;
the underlying single encrypted record has a stricter 64 KiB plaintext
limit. Oversized changes reject without altering existing data.

## Verification

Run `node --test tools/local-agent/tests/*vault.test.mjs`.
All fixtures are fictional and temporary directories are removed after tests.
Tests cover encryption/no plaintext on disk, wrong unlock, tampering, unsafe
permissions, file locks, adapters, malformed CSV, URL rejection, atomic
conflicts, metadata-only search, recovery separation and concurrent imports.

## Remaining P0 gates

- Trusted local unlock/import/search interface and recovery workflow.
- Review encrypted backup/restore and format migration before real use.
- Dedicated local credentials directory and OS ACL validation on Windows.
- Independent security review, fuzzing and real export compatibility checks
  using consented synthetic accounts (not user credentials).
- Authenticated metadata-only integration with ATLAS Work/ChatGPT, with
  authorization/revocation tests; no secret-returning tool.
- Current canonical HEAD reconciliation, exact-SHA CI and runtime E2E.

No merge, deploy, production write or real secret access is authorized by
this implementation. Keep existing Apple/Google entries unchanged.
